# Dacian Scrolls Vertical Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan one work package (WP) at a time. You are given ONE work package. Read `CLAUDE.md`, then `docs/CONTRACTS.md`, then sections 1 to 5 here, then your own package in section 7. **Where section 4 and `docs/CONTRACTS.md` differ, CONTRACTS.md and the code stubs win.** Do not read other packages unless yours names them. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 20 to 30 minute playable slice around Sarmizegetusa: world map travel with fog and encounters, one town, one dungeon, one crash site, turn-based AP combat with 2 playable classes and 1 companion, one UFO abduction with a mini-boss, save and load, one adaptive music track.

**Architecture:** A deterministic, pure-logic simulation core (`src/core/`, no scene tree, seeded RNG, plain dictionaries in and out) that every mode drives through actions and reads back as events. Thin Godot scenes only play those events. All content is JSON, all maps are text grids built at runtime, and all art and audio are generated by scripts, so every part of the game is text an agent can write, diff and test headless.

**Tech Stack:** Godot 4.5.1-stable, GDScript only, a small built-in test runner (`tests/framework/`, GUT could not be fetched here), Python 3 with Pillow and numpy for asset generation, ffmpeg for OGG encoding, GitHub Actions for CI and builds.

**Spec:** [Dacian Scrolls: Game Plan](https://claude.ai/artifact/KSp3BF4KU1JPb3CQB6xNxk), sections "First milestone", "Game design", "Design lens" and "Technical architecture". A text export is committed by WP-00 as `docs/spec/game-plan.md`. Where this plan and the spec differ, section 2 says why.

---

## 1. Why the plan is shaped this way

Subagents have three weaknesses on a game project. Each structural choice below removes one.

| Weakness | Choice that removes it |
|---|---|
| They cannot see or click the game | The core is pure logic. A battle, a journey or a dialogue runs in a headless test with a seed and gives the same result every time. A bot plays the whole slice in CI. |
| They cannot use the Godot editor | No hand-authored scenes beyond trivial ones. Maps are ASCII grids in JSON, content is JSON, UI is built in code from a small kit. Nothing needs a mouse. |
| Parallel agents collide and drift | Contracts first (WP-00 freezes every interface and schema), then exclusive file ownership per package. Two packages never edit the same file. |

Two more choices keep the work from blocking:

- **Placeholders by default.** `Assets.tex(id)` and `Audio.sfx(id)` return a labelled placeholder when the real file is missing. Code never waits on art or music.
- **One rules mini-language.** Dialogue choices, quest steps, encounter options and map triggers all use the same condition and effect lists (section 4.5). One interpreter, one set of tests, and content writers learn one thing.

## 2. Decisions and deviations from the spec

| Topic | Decision | Reason |
|---|---|---|
| Content format | JSON files validated against schemas, not Godot `.tres` Resources | `.tres` files carry editor-generated ids and break when hand-written. JSON is safe for agents and easy for Cojo's associate to mod. |
| Dialogue | Own small JSON format, no Dialogic or Dialogue Manager | Plugins assume an editor workflow. Our format reuses the rules mini-language. |
| Maps | ASCII grid JSON built at runtime by `MapBuilder` | TileMap scenes cannot be written reliably as text. |
| Tests | Own ~150-line runner instead of GUT; engine errors fail tests | GUT's archive is blocked by the build environment's proxy. The runner also catches script errors, which GUT does not by default. |
| Art style | Pixel art, 64x32 isometric tiles, locked 32-colour palette, generated by Python scripts | Open question in the spec. Pixel art is what generated art does most reliably. Gated by a style spike that Cojo approves (WP-14). |
| Language | English strings, every player-facing string behind a key in `data/strings/en.csv` | Open question in the spec. Romanian becomes a second CSV later, no code changes. |
| Height in combat | Deferred. Cover and flanking are in. | Height needs multi-level maps, which the slice does not have. |
| Survival-lite | Food only: 1 food per party member per day, starving costs HP | Smallest version that makes the fast road versus safe forest choice real. |
| Final boss, approval, crafting, other regions | Out of scope | As in the spec. |

**Verified in WP-00:** Godot 4.5.1 runs headless in the agent container, and `tools/shots.sh` renders real screenshots through xvfb, so view packages can look at their work.

## 3. Global Constraints

- Godot `4.5.1-stable` exactly. `tools/get_godot.sh` downloads it to `.godot-bin/` (git-ignored). Do not use APIs newer than 4.5.
- GDScript only, static typing on every function signature. No C#, no GDExtension, no editor plugins.
- `src/core/**` must not reference `Node`, `SceneTree`, autoloads, `randi()`, `randf()`, `Time` or the file system. Randomness comes only from an injected `Rng`. A lint test enforces this (WP-00).
- Base resolution 640x360, integer scaling, stretch mode `canvas_items`, aspect `keep`. Nearest-neighbour filtering.
- Tiles are 64x32 isometric diamonds. Human sprites are 32x48 on a 1x1 cell. Giants use a 2x2 footprint and a 128x192 sprite that shows legs to the waist only; the rest is off the top of the screen. That is a deliberate joke: you fight the ankles.
- No player-facing string literals in code. Use `tr("key")` with keys from `data/strings/en.csv`.
- XP never comes from kills. It comes from pages, discoveries, quest stages and salvage (spec, Design lens 1).
- Every encounter offers at least 2 options (spec, Design lens 5). The data validator rejects an encounter with fewer.
- At most 4 equipped abilities per character (spec, Design lens 4).
- Gore has three settings, `0` Off, `1` Normal, `2` Bloody Mess. Gore is presentation only and never changes simulation results.
- Tone: the world takes itself seriously, the narrator Fanfi does not. Deadpan, self-aware, no more than one meme reference per scene. Splatter comedy, not grim.
- The slice uses base 12 where it can: 12 scroll pages, prices in multiples of 12.
- Each package touches only the files it owns. A needed change elsewhere is a contract change request (section 6.3), not an edit.
- Commits are small and each one leaves `tools/test.sh` green.

### 4.4 Events and actions

Every core call that changes anything returns `Array[Dictionary]` of events, each with a `type` key. Views play events back in order. Views never compute outcomes. The full list lives in `docs/CONTRACTS.md`; the main ones:

- Combat: `turn_started{unit}`, `moved{unit, path}`, `ability_used{unit, ability, cell}`, `missed{unit, target}`, `damaged{target, amount, crit}`, `healed{target, amount}`, `status{target, status, turns}`, `died{target, gib: bool}`, `summoned{unit, cell}`, `rule_changed{rule, value}`, `timer{turns_left}`, `battle_ended{outcome}`.
- World: `stepped{pos, hours}`, `revealed{cells}`, `discovered{location}`, `food_changed{food}`, `starved{amount}`, `encounter{encounter_id}`, `ufo_moved{id, pos, state}`, `abducted{ufo_id}`.
- Story: `flag_set`, `item_changed{item, delta}`, `gold_changed{delta}`, `quest_changed{quest, stage}`, `page_found{page}`, `xp_gained{amount}`, `level_up{unit}`, `recruited{unit}`, `battle_requested{encounter_id}`, `shop_requested{shop_id}`, `narrator{line_key}`.

Combat actions are dictionaries: `{type: "move", path: Array[Vector2i]}`, `{type: "ability", ability: StringName, cell: Vector2i}`, `{type: "item", item: StringName, cell: Vector2i}`, `{type: "end_turn"}`, `{type: "flee"}`.

### 4.5 Rules mini-language

`Rules` (`src/core/rules.gd`): `static check(conds: Array, state: GameState) -> bool` (all must hold, empty is true) and `static run(effects: Array, state: GameState, rng: Rng) -> Array[Dictionary]`.

Conditions: `["flag", name, op, value]`, `["quest", id, op, stage]`, `["has_item", id, count]`, `["gold", op, n]`, `["class", class_id]` (hero), `["in_party", character_id]`, `["has_page", id]`, `["stat", stat, op, n]` (best in party), `["night"]`, `["not", cond]`, `["any", [conds]]`. `op` is one of `== != >= <= > <`.

Effects: `["set_flag", name, value]`, `["give_item", id, n]`, `["take_item", id, n]`, `["gold", delta]`, `["food", delta]`, `["quest", id, stage]`, `["page", id]`, `["xp", n]`, `["recruit", character_id]`, `["heal_party"]`, `["battle", encounter_id]`, `["shop", shop_id]`, `["discover", location_id]`, `["teleport", location_id]`, `["narrate", line_key]`, `["roll", stat, dc, [effects_pass], [effects_fail]]`.

An unknown condition is false and an unknown effect is skipped; both log an error. The validator rejects them in data before they can run.

### 4.6 Data schemas (key fields)

- **class**: `id, name_key, base_stats{might,agility,wits,spirit}, hp_per_level, abilities: [ability_id], sprite`
- **ability**: `id, name_key, desc_key, source: "steel"|"magic"|"tech", ap: int, cost: int` (mana for magic, charge for tech, 0 for steel), `range: int, area: int, target: "enemy"|"ally"|"cell"|"corpse"|"self", effects: [{kind, ...}]` where `kind` is one of `damage heal shield taunt status summon cleanse push`
- **item**: `id, name_key, kind: "weapon"|"armor"|"trinket"|"consumable"|"quest"|"salvage", price, mods{}, use_effects[]`
- **enemy**: `id, name_key, size: 1|2, hp, stats{}, armor, abilities[], ai: "brute"|"skirmisher"|"caster"|"boss_surgeon", raiseable: bool, loot: [{item, chance}], sprite, gib: bool`
- **encounter**: `id, intro_key, map, enemies: [{enemy, cell}], options: [{id: "fight"|"talk"|"sneak"|"bribe"|"flee", label_key, if: [conds], roll: {stat, dc} or null, pass: [effects], fail: [effects]}], rules: {magic_disabled: bool, gravity: "normal"|"floaty", turn_limit: int}`
- **map**: `id, kind: "town"|"outskirts"|"dungeon"|"arena", legend: {char: tile_id}, ground: [rows], objects: [rows], entities: [{id, kind: "npc"|"container"|"exit"|"trigger"|"spawn_ally"|"spawn_enemy", cell: [x,y], ...}]`. Tile ids carry `walkable` and `cover: 0|20|40` in `data/maps/tiles.json`.
- **dialogue**: `id, start, nodes: {node_id: {speaker, text_key, do: [effects], choices: [{text_key, if: [conds], do: [effects], goto: node_id or "end"}]}}`
- **quest**: `id, name_key, stages: {int: desc_key}, xp_on_done`
- **page**: `id, title_key, body_key, order: 1..12`
- **world.json**: `size: [48, 32], terrain: [rows], legend, locations: [{id, cell, map, hidden: bool}], ufos: [{id, route: [cells], encounter}], tables: {terrain: [{encounter, weight}]}`. Terrain table:

| Terrain | Hours per cell | Encounter chance per cell | Hides party from UFOs |
|---|---|---|---|
| road | 1 | 6% | no |
| plains | 2 | 10% | no |
| forest | 4 | 12% | yes |
| mountain | 6 | 15% | no |
| river | impassable | | |

### 4.7 Combat formulas (`src/core/combat/formulas.gd`)

- AP per turn: `6 + agility / 2` (integer division). Moving costs 1 AP per cell, 2 while gravity is `floaty`.
- Initiative: `agility + d6`, ties go to the party, then to list order.
- Hit chance: `clamp(75 + 5 * (attacker.agility - target.agility) - cover + flank, 5, 95)`. `cover` is the tile value between attacker and target for ranged attacks, 0 for melee. `flank` is 15 when an ally of the attacker stands on the opposite side of the target.
- Damage: `max(1, base + might_or_wits * scale - armor)`. Crit on a d20 roll of 20: double damage, and `died.gib` is true.
- Floaty gravity: every `push` moves 2 extra cells and a unit that ends its move rolls 25% to drift 1 cell in a random direction.
- Magic disabled: abilities with `source: "magic"` are absent from `legal_actions`.
- Leveling: level N needs `120 * N` XP. Each level gives `hp_per_level` max HP and +1 to the class's top stat.

## 5. Review Focus

Conditions the spec does not mention that will bite a real player. Each has a test in the package that owns the code.

1. **A save file that is corrupt, empty or from an older version.** Loading must fail with a message and leave the current game untouched, never crash. Test in WP-10.
2. **Content that refers to a missing id** (an ability, a sprite, a string key). The validator fails CI; at runtime the game shows a placeholder and keeps running. Tests in WP-00.
3. **A unit with no legal move** (boxed in, 0 AP, all abilities unaffordable). `legal_actions` always contains `end_turn`, and a battle always ends within `turn_limit` or 60 rounds. Test in WP-12.
4. **Travel with no food, or to an unreachable cell.** Starving costs HP but never kills the last party member; an unreachable destination returns an empty path and no time passes. Test in WP-13.
5. **Quitting or loading in the middle of an abduction or battle.** Saves happen only at mode changes, so a reload returns to the last safe point, before the beam. Test in WP-30.

### 6.2 Rules for every package

- Branch `wp/NN-short-name` in its own git worktree, one PR to `main`.
- Test first. Write the failing test, run it, implement, run it, commit.
- Done means: `tools/test.sh` green, `python3 tools/validate_data.py` green, only owned files changed, and `docs/handoff/WP-NN.md` written (what exists, how to call it, known gaps, 15 lines at most).
- A fresh reviewer agent checks each PR against its package card and the Global Constraints before merge.
- View packages also run `tools/shots.sh <scene>` and look at the PNGs before claiming done.

### 6.3 Contract change requests

If a package needs a contract changed, the agent stops, writes the request in its handoff file (what, why, which packages it affects) and reports back. The orchestrator edits `docs/CONTRACTS.md` and the stubs on `main`, then tells affected agents. Agents never edit contracts themselves.

- [ ] Formulas, exact values: agility 4 gives 8 AP; attacker agility 6 against target agility 4 with cover 20 and no flank gives 65% hit; that clamps to 95 at most and 5 at least; base 6, might 5, scale 1.0, armor 3 gives 8 damage; base 1 against armor 9 gives 1.

### WP-13: World travel, fog, encounters and UFOs

**Owns:** `src/core/world/*`, `tests/unit/test_travel.gd`, `tests/unit/test_ufo.gd`.

**Consumes:** `GameState`, `Rng`, `Rules`, `Content`. **Produces:**

```
Travel.path(state: GameState, to: Vector2i) -> Array[Vector2i]     # empty if unreachable
Travel.step(state: GameState, next: Vector2i, rng: Rng) -> Array[Dictionary]
Encounters.options(encounter_id: StringName, state: GameState) -> Array[Dictionary]
Encounters.choose(encounter_id: StringName, option_id: String, state: GameState, rng: Rng) -> Array[Dictionary]
Ufo.tick(state: GameState, rng: Rng) -> Array[Dictionary]
```

`Travel.step` advances time by the terrain's hours, eats food at each day rollover, reveals fog in radius 2, discovers a non-hidden location within radius 1, rolls the terrain's encounter chance, then calls `Ufo.tick`. The caller stops the journey on `encounter`, `abducted` or `discovered`.

- [ ] Terrain table from section 4.6: a path of 3 road cells from hour 8 ends at hour 11; forest costs 4 hours a cell; river is never in a path.
- [ ] Fog: after one step, exactly the cells within radius 2 are in `revealed`.
- [ ] Food: crossing midnight with a party of 3 removes 3 food. Review Focus 4: at 0 food each member loses 2 HP per day, emitting `starved`, and no one drops below 1 HP. `Travel.path` to a cell enclosed by river is `[]` and `step` is never called.
- [ ] UFO: follows its `route` in `patrol`; switches to `chase` when the party is within 5 cells (2 at night) and not in forest; moves 2 cells per party step while chasing; returns to patrol when the party enters forest; emits `abducted` when on the party's cell. Flag `decoy_charm` makes it ignore the party once and clears the flag.
- [ ] Encounters: `options` hides options whose `if` fails but never returns fewer than 2 (it always keeps `fight` and `flee`); `choose` with a `roll` runs `pass` or `fail`; resolving by `talk`, `sneak` or `bribe` grants the same XP as fighting.
- [ ] Encounter chance is 0 for 3 steps after any encounter, so the player is not chain-ambushed.
