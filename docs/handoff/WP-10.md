# WP-10 handoff: state and save

- `Character.create/to_dict/from_dict/gain_xp` plus public `level_up(class_def)` and `top_stat(class_def)`. XP is progress inside the current level (`xp -= xp_to_next` on each level up, multi-level grants emit several `level_up`).
- `GameState.to_dict()` is JSON-safe: cells are `[x, y]`, ids strings, `seed`/`rng_state` decimal strings (64-bit ints do not survive JSON numbers). `from_dict` is lenient; validation lives in `SaveCodec`.
- `SaveCodec.decode` checks JSON, version (`< 1` or non-int corrupt, `> VERSION` `save_too_new`), every top-level key and its type, and every party member field (party 1..4). Never pushes errors.
- `Game.new_game(seed, class)` per CONTRACTS 5 (uses `Rules.reveal_around` and `Rules.location`). `Game.save(slot)` stores `rng_state`, writes `save_N.json.tmp` then renames; bad slot pushes an error. `Game.load_slot` toasts the error key and leaves `state` and `rng` untouched.
- Tests: `test_state.gd`, `test_save.gd`, `test_game.gd` (saves under `user://test_saves`), helper `tests/unit/fxs_state_helpers.gd`.
- Gap: `data/` has no `world.json` yet, so `new_game` on real data pushes an error until WP-17 lands. `hero_name` is not yet in any strings csv (WP-18).
- Change request: a missing save slot toasts `save_corrupt`; a `save_missing` key ("No save in that slot.") in `data/strings/en.csv` would read better (affects WP-10, WP-16).
